# dagger-rs — راهنمای فارسی

بازنویسی مستقل تونل شبکه با Rust برای لینوکس. اعتبار نویسندهٔ اولیه: [ir_spoof](https://t.me/ir_spoof). مجوز MIT و اعلان‌های وابستگی‌ها حفظ شده‌اند.

## نسخه و سازگاری

نسخهٔ سورس موجود **0.2.1** است. **4.2.8-stable** نسخهٔ DaggerConnect مرجع است، نه نسخهٔ این بستهٔ Rust. این پروژه پروتکل احراز هویت و فریم‌بندی مستقل دارد و با کلاینت یا سرور اصلی DaggerConnect سازگار نیست.

در سورس مسیرهای TCP، KCP، HTTP/HTTPS، WS/WSS، XHTTP/XHTTPS، DC6، Quantum+، Quantum/Gaming و Raw TUN وجود دارند. وجود کد به معنی تأیید عملکرد در تمام شبکه‌ها نیست. محدودیت‌ها در [گزارش بازسازی](docs/reconstruction.md) و [مدل امنیتی](docs/security.md) آمده‌اند.

## نصب از GitHub Releases

پس از انتشار موفق بسته در [Releases](https://github.com/V2grop/dagger-connect-rs/releases)، روی هر سرور Ubuntu/Debian با معماری x86-64 اجرا کنید:

```sh
sudo apt-get update && sudo apt-get install -y ca-certificates curl python3
curl -fL https://raw.githubusercontent.com/V2grop/dagger-connect-rs/main/scripts/install-release.sh -o install-dagger.sh && sudo bash install-dagger.sh
```

اسکریپت نسخهٔ منتشرشده را انتخاب می‌کند، فایل نصب و checksum همان نسخه را می‌گیرد، صحت فایل را بررسی و منوی تنظیمات را باز می‌کند. اگر هنوز Release ساخته نشده باشد، نصب متوقف می‌شود. دفعات بعد:

```sh
sudo /usr/local/bin/dagger-setup
```

برای راه‌اندازی ساده از منوی سادهٔ انگلیسی استفاده کنید:

```sh
sudo /usr/local/bin/dagger-setup-classic
```

گزینهٔ ۱ برای ایران و ۲ برای خارج است. راهنمای مرحله‌به‌مرحله در ادامه آمده است.

## ساخت

روی لینوکس با Rust پایدار و ابزارهای ساخت بومی:

```sh
cargo build --locked --release
cargo fmt --all -- --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked --release --all-targets
python3 -m unittest discover -s tests -p 'test_install.py' -v
```

باینری حاصل در `target/release/dagger-rs` است. راهنمای انگلیسی روش بسته‌بندی و تست‌های شبکه با دسترسی ویژه را توضیح می‌دهد.

## راه‌اندازی دو میزبان

روی سرور و کلاینت کلید جداگانه بسازید:

```sh
# سرور
target/release/dagger-rs keygen --out keys/server
# کلاینت
target/release/dagger-rs keygen --out keys/client
```

نمونه‌های `examples/server.json` و `examples/client.json` را در پوشهٔ `config` کپی کنید. مسیر کلید خصوصی هر میزبان، کلید عمومی طرف مقابل، آدرس سرور و پورت مقصد را تنظیم کنید. کلید خصوصی را منتقل نکنید. مسیر فایل‌ها نسبت به فایل تنظیمات تفسیر می‌شود.

```sh
target/release/dagger-rs --config config/server.json --check
target/release/dagger-rs --config config/server.json
# روی کلاینت، از config/client.json استفاده کنید.
```

`allowed_targets` خالی همهٔ مقصدهای فوروارد را رد می‌کند؛ `*` همه را مجاز می‌کند. SOCKS5 فقط CONNECT دارد؛ احراز هویت کاربری و UDP ASSOCIATE پیاده نشده‌اند. TUN به CAP_NET_ADMIN و مسیرهای خام به CAP_NET_RAW نیاز دارند. پورت‌های فوروارد و SOCKS را با فایروال محدود کنید.

## اصلاحات نگه‌داری

نصب‌کننده هنگام جایگزینی `dagger-setup` دیگر فایل مقصد لینک نمادین را بازنویسی نمی‌کند. سه تست نصب و راه‌اندازی مجدد به CI اضافه شده است. کامپایل Rust و آزمون مستقل پروتکل‌ها در محیط این بررسی اجرا نشده‌اند؛ جزئیات در [گزارش بررسی](docs/maintenance-review.md) هستند.


## منوی دوم با سبک نسخهٔ اصلی

منوی جدید را V2grop برای هستهٔ مستقل Rust طراحی کرده است. چیدمان آن از منوی
itsFLoKi/DaggerConnect الهام گرفته؛ هسته، مجوز یا سازگاری نسخهٔ اصلی را اضافه نمی‌کند.
منوی قبلی همچنان موجود است. هر دو منو از کلیدها، تنظیمات و سرویس‌های یکسان استفاده می‌کنند.

روی Ubuntu/Debian با معماری x86-64:

```bash
curl -fLO https://raw.githubusercontent.com/V2grop/dagger-connect-rs/main/setup.sh
chmod +x setup.sh
sudo ./setup.sh
```

این ورودی آخرین ریلیز V2grop را با بررسی SHA256 نصب می‌کند و منوی دوم را باز می‌کند.
نصب مجدد تنظیمات را حفظ می‌کند؛ سرویس‌های در حال اجرا خودکار ری‌استارت نمی‌شوند.

```bash
sudo /usr/local/bin/dagger-setup-classic  # منوی دوم
sudo /usr/local/bin/dagger-setup          # منوی قبلی
```

### راه‌اندازی ساده با گزینه‌های ۱ و ۲

در این برنامه `server` یعنی **سرور ایران** و `client` یعنی **سرور خارج**؛
منظور از client گوشی یا برنامهٔ کاربر نیست. گوشی به IP ایران و پورت ورودی کاربران وصل می‌شود.

ابتدا روی هر دو سرور گزینهٔ **۱۵** را بزنید. برای نقش همین سرور، **۱ ایران** یا
**۲ خارج** را انتخاب کنید. کلید عمومی ایران را روی خارج و کلید عمومی خارج را روی ایران وارد کنید.
کلید خصوصی جابه‌جا نمی‌شود. اگر کلید طرف مقابل آماده نیست Enter خالی شما را به منو برمی‌گرداند.

مثال زیر فرض می‌کند **اینباند TCP روی خارج با پورت ۲۰۳۰ فعال است**. اگر اینباند
شما پورت دیگری دارد همان را جایگزین کنید؛ پورت صفحهٔ مدیریت پنل مقصد تونل نیست.

| سؤال | روی ایران: گزینهٔ ۱ | روی خارج: گزینهٔ ۲ |
|---|---|---|
| کلید طرف مقابل | کلید عمومی خارج | کلید عمومی ایران |
| روش تونل | ۱ برای TCP، ۲ برای Quantum+، ۳ برای KCP | دقیقاً همان روش ایران |
| IP سرور ایران | پرسیده نمی‌شود؛ شنود خودکار روی همهٔ رابط‌های ایران | IP واقعی ایران، بدون پورت |
| پورت تونل ایران | `7000` | همان `7000` |
| نوع ترافیک اینباند | ۱ برای TCP یا ۲ برای UDP | از سمت ایران تعیین می‌شود |
| پورت ورودی کاربران روی ایران | مثلاً `18080` | پرسیده نمی‌شود |
| آدرس سرویس از دید خارج | `127.0.0.1` برای سرویس روی خود خارج | دقیقاً همان `127.0.0.1` |
| پورت سرویس خارج | `2030` در این مثال | همان `2030` |

هر سؤالِ پورت فقط **عدد** می‌خواهد؛ `IP:PORT` را خودتان نسازید. ارقام فارسی هم پذیرفته می‌شوند.
در سؤال مقصد، `127.0.0.1` همیشه یعنی **لوکال خارج**، حتی اگر الان در ترمینال ایران هستید.
اگر سرویس در Docker یا دستگاه دیگری است، آدرسی بدهید که از سرور خارج قابل دسترسی باشد؛
این آدرس باید در تنظیم هر دو طرف یکسان نوشته شود.

قبل از ذخیره، خلاصهٔ نقش سرور، روش تونل، ورودی ایران و مقصد خارج نمایش داده می‌شود.
۱ = تأیید ذخیره، ۲ = لغو. `q` در سؤال‌های راه‌اندازی ساده به منو برمی‌گردد؛
لغو قبل از ذخیره، تنظیم قبلی را حفظ می‌کند. Enter مقدار داخل کروشه را می‌پذیرد؛
پورت سرویس خارج پیش‌فرض ندارد و باید پورت واقعی خودتان را وارد کنید.

بعد از ذخیره، راه‌اندازی سرویس همین سرور را با **۱ یا Enter** تأیید کنید.
۲ یعنی فقط ذخیره؛ برای فعال‌کردن بعدی گزینهٔ **۱۴** را بزنید.
در کانفیگ گوشی **IP ایران و پورت ۱۸۰۸۰** را قرار دهید؛ سایر تنظیمات باید با اینباند خارج یکسان بماند.
پورت تونل ایران و ورودی کاربران باید در فایروال مجاز باشند؛ TCP برای روش TCP و UDP برای
Quantum+/KCP. پروتکل ورودی کاربران همان TCP/UDP انتخاب‌شده برای اینباند است.

گزینهٔ **۱۳** عیب‌یابی، **۶** گزارش اخیر و **۷** گزارش زنده است. فعال‌بودن سرویس به‌تنهایی
اثبات عبور داده نیست؛ کانفیگ کاربر را هم امتحان کنید. این تونل خودش اینباند یا سرویس VPN نمی‌سازد.

گزینهٔ **۱۲** منوی پیشرفتهٔ قبلی را برای TLS، TUN، SOCKS و سایر حامل‌ها باز می‌کند.
هسته و پروتکل‌ها تغییر نکرده‌اند. منوی ساده فقط یک مسیر انتقال پورت را تنظیم می‌کند؛
برای چند مسیر یا تنظیم تخصصی از منوی پیشرفته استفاده کنید.

### تطبیق با سورس ارسالی

بستهٔ ارسالی با نام `DaggerConnect-4.2.8-stable-resync (1).zip` درون خود سورس و
باینری **dagger-rs 0.2.1** دارد. کد Rust، وابستگی‌ها و پروتکل این نسخه با آن سورس
یکسان‌اند؛ اصلاح حاضر مربوط به نصب و منو است. جزئیات مقایسه و تست عبور واقعی
داده در [گزارش اصلاح راه‌اندازی](docs/setup-repair.md) آمده است.

### برچسب‌های انگلیسی منو

منو انگلیسی است. `[IRAN] Server IP` آی‌پی ایران، `[IRAN] Tunnel Port` پورت تونل ایران،
`[IRAN] User Port` پورت اتصال کاربران، `[ABROAD] Service IP` آدرس سرویس از دید خارج و
`[ABROAD] Service Port` پورت اینباند خارج است. `Client` در منو یعنی سرور خارج، نه گوشی.
`[KEY]` کلید عمومی، `[CHECK]` بازبینی/عیب‌یابی و `[SAVE]` ذخیره را مشخص می‌کنند.
